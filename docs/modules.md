# Panduan Modul Aplikasi

Dokumen ini merinci fitur dan fungsi dari setiap modul utama yang tersedia di Trainers SuperApp.

Konvensi nama modul:

- **KETIK** = Kelas Etika & Trik Komunikasi
- **PDKT** = Paham Dulu Kasih Tanggapan
- **TELEFUN** = Telephone Fun
- **KTP** = Kotak Tool Profil
- **SIDAK** = Sistem Informasi Data Analisis Kualitas

## 1. Unified Dashboard

Dashboard tunggal yang berfungsi sebagai pusat informasi bagi semua tingkatan user.

- **Fungsi**: Menampilkan KPI ringkasan, grafik tren, dan log aktivitas terbaru.
- **Route**: `/dashboard`
- **Fitur Utama**:
  - **Beranda agent (fase 4)**: Salam → **Skor QA saya** (skor audit terakhir vs target 95, perubahan versus audit sebelumnya, tren maksimal 6 periode lintas tahun, 3 parameter temuan teratas dan satu saran deterministik) → **Latihan** dengan kuota harian/reset WIB → **Riwayat sesi** gabungan KETIK, PDKT dan Telefun, maksimal 5 terbaru. Skala Telefun tetap /10, KETIK/PDKT /100. Jika beberapa layanan diaudit pada bulan terbaru, layanan tim diprioritaskan; jika tidak ada, pilih layanan valid secara deterministik. Label layanan ditampilkan dan tren tidak mencampur layanan. Phantom-only tidak dianggap audit nyata; skor 0 tetap data.
  - **Privasi QA agent**: `GET /api/v1/home/agent-summary` hanya untuk role agent dengan `sidak.dashboard.read`, tidak menerima ID/filter dari klien. Scope self dari akun tertaut; respons `AgentHomeSummary` hanya agregat whitelist, tanpa data KTP, nama agent lain, catatan QA, nomor tiket atau pembanding layanan. Akun belum tertaut mendapat petunjuk menghubungi trainer (`linked:false`); tertaut tanpa audit tetap dibedakan (`linked:true, qa:null`). Error sumber menghasilkan 503 ramah, bukan sukses kosong. Latihan tetap tersedia jika QA/kuota/riwayat gagal. Detail teknis dan bukti: [fase 4](../plans/markdown/dashboard-wsn.md#11-tahap-4--beranda-agent-disetujui-implementasi).
  - **Perlu tindakan (staff)**: Agen di bawah target menampilkan maksimal tiga nama dengan skor terendah dan jumlah sisanya, hanya dari scope pengguna. Tombol `Lihat N agen` membuka `/sidak/agents?status=below`, dengan filter **Di bawah target 95** aktif; nilai status tak dikenal diabaikan tanpa membuang cakupan SIDAK.
  - **Tren Performa Kualitas (staff)**: Grafik temuan QA tahun berjalan dengan filter layanan dan rentang bulan. Stat **Per agen diaudit** memakai jumlah agen pada periode terakhir (per layanan bila dipilih); kalimat deterministik membedakan perubahan laju dari perubahan volume audit. Delta jumlah mentah netral. Tautan **Lihat penyebab di SIDAK** membawa layanan (kecuali Semua layanan), tahun, dan **bulan periode terakhir berdata**, bukan seluruh rentang.
  - **Temuan per layanan (staff)**: Jumlah dan porsi dari periode terakhir, dengan perubahan versus periode sebelumnya. Layanan yang turun menjadi nol tetap terlihat dengan −100%; baseline nol tidak menghasilkan persentase buatan. Layanan dengan kenaikan terbesar ≥5% ditandai dalam kalimat dan menjadi filter tautan SIDAK.
  - **Pintasan Cepat**: Navigasi role-aware menuju pekerjaan modul, dengan target klik dan label yang jelas.
  - **Monitoring**: (Trainer/Leader/Admin) Memantau histori simulasi lintas akun yang dipaginasi penuh dari source canonical KETIK/PDKT/Telefun tanpa cap tersembunyi, agregasi penggunaan token bulanan, dan editor harga/kurs untuk role yang diizinkan; detail menampilkan metadata served-consumer dan assessment native per modul, sedangkan row Telefun legacy hanya kompatibilitas bila tidak ada row canonical.
  - **User Management**: (Hanya Admin) Menyetujui pendaftaran, mengubah role, atau menghapus akun.
- **Sub-pages**:
  - `/dashboard/access-approval`: Approval akses leader ke data KTP dan SIDAK.
  - `/dashboard/access-groups`: Manajemen access groups untuk leader scope.
  - `/dashboard/activities`: Log aktivitas sistem (search/filter/pagination/CSV export/delete). Admin dan Trainer dapat melihat semua aktivitas lintas modul (SIDAK, Profiler, User Management).
  - `/dashboard/users`: Manajemen user (admin only).
- **Catatan Teknis**: Halaman `/monitoring` adalah permukaan terproteksi utama untuk monitoring AI usage dengan 3 tab: `Riwayat`, `Biaya AI` (`/monitoring/biaya`, rincian per orang di `/monitoring/biaya/:pengguna`), `Harga & kurs`. Riwayat membaca source sampai habis lewat paging offset-range deterministik, fail-closed dengan 500 jika source/page/profile/coaching read gagal, urutan equal timestamp memakai tie-breaker `id`, memuat metadata served-consumer KETIK/PDKT/Telefun, assessment native lengkap, thread/transcript penuh, dan Telefun coaching recommendations runtime-normalized dari `telefun_coaching_summary`. Periode default penggunaan token selalu mengikuti WIB / `Asia/Jakarta`, bukan timezone browser. Hanya trainer/admin yang dapat mengedit pricing/kurs; leader hanya read-only untuk history + biaya, dan hanya untuk akun/peserta di tim yang aksesnya disetujui.

## 2. KETIK (Kelas Etika & Trik Komunikasi)

Ruang simulasi untuk melatih kemampuan komunikasi tertulis melalui media chat.

- **Fungsi**: Peserta berinteraksi dengan AI yang berperan sebagai pelanggan dalam berbagai skenario.
- **Routes**: `/ketik` (landing + ruang chat; tahap Telaah di `/ketik?sesi=<id>&tahap=telaah`), `/ketik/history` (tabel riwayat), `/ketik/simulation` (alias lama, dialihkan ke `/ketik`)
- **Fitur Utama**:
  - **Skenario Dinamis**: Latihan berdasarkan berbagai tingkat kesulitan.
  - **Roleplay Konsumen**: Balasan AI difokuskan sebagai konsumen chat natural, bukan evaluator.
  - **Riwayat Sesi**: Halaman `/ketik/history` berisi tabel sesi dengan filter status, pencarian, unduh CSV, putar ulang, dan hapus lewat dialog konfirmasi aplikasi.
  - **Tahap Telaah**: Setelah chat diakhiri (dengan konfirmasi), sesi disimpan lalu pengguna masuk tahap Telaah: transkrip bernomor di kiri, skor akhir, lima aspek, dan tab Perbaiki dulu / Sudah baik / Ejaan / Ringkasan di kanan. Status telaah ditampilkan apa adanya (belum ditelaah, sedang ditelaah, gagal, selesai) tanpa persentase buatan. Saat queued/processing, panel menampilkan waktu berjalan serta estimasi jujur “biasanya 1–2 menit, paling lama sekitar 3 menit”, lalu menandai bila lebih lama dari biasanya.
  - **AI Review**: Evaluasi AI menggunakan rubrik Bahasa Indonesia dengan skala `0-100`.
  - **Monitoring detail**: `/monitoring` menampilkan `consumer_name`, `consumer_phone`, `consumer_city`, `simulationDuration`, transcript lengkap, dan score native; jika `consumer_name` hilang, API tetap null dan UI menampilkan unavailable, bukan placeholder buatan.
  - **Usage Bulanan**: Popover `Pemakaian AI` di menu landing (komponen bersama dengan PDKT) dengan indikator biaya sesi terakhir (`+Rp`).
  - **Scenario Image Safety**: Lampiran gambar diakumulasi secara functional; FileReader yang terlambat, pending, atau gagal tidak bisa menimpa draft yang sudah ditutup atau dibuka ulang.
  - **Template Cepat Standar + Pribadi**: Daftar template standar KETIK dikelola admin dan dibaca sama oleh seluruh user. Setiap user juga dapat menambah, mengubah, dan menghapus template pribadi yang hanya aktif di akunnya; shortcut `/` menampilkan keduanya.
- **Akses**: Empat role kanonis `admin`, `trainer`, `leader`, dan `agent` dapat memakai simulasi/pengaturan KETIK. Agen/leader dapat menelaah sesi sendiri secara manual; trainer dapat menelaah sesi sendiri dan penerima assignment yang dikelolanya; admin dapat seluruh sesi. Daftar/summary tetap akun sendiri. Detail/deep-link diotorisasi dengan scope telaah yang sama.
- **Catatan Teknis**: KETIK menyimpan history chat di `ketik_history`. Review AI bersifat manual — user memicu review setelah sesi selesai. Backend API di `/api/v1/ketik/` menangani chat, review, history, dan settings.
  - **Tempo chat**: Konsumen menunggu agen berhenti mengetik selama 5 detik atau sampai draf dikosongkan; penahanan dibatasi 30 detik (realistic) / 15 detik (training fast), dan dilewati saat penutupan atau sisa waktu kurang dari 20 detik. Jeda setelah kirim adalah 8 detik (realistic) / 3 detik (training fast), dikalikan faktor kecepatan konsumen.
  - **Manual-only review**: Analisis AI hanya dimulai dari tombol "Mulai telaah" oleh user, bukan otomatis saat sesi selesai.
  - **Retry after failure**: Jika review gagal, user dapat mengklik "Coba telaah lagi" untuk retry. Job status di-reset dari `failed` ke `queued`.
  - **Status reconciliation**: Polling read-only membaca snapshot job + hasil tersimpan; antrean lama/lease expired dipulihkan worker, bukan digagalkan oleh browser.
  - **Scenario image safety**: Lampiran gambar ditambah dengan akumulasi functional; callback FileReader yang terlambat, pending, atau errored diabaikan, dan save tidak jalan sampai pembacaan selesai.
  - **Save & reset safety**: Save scenario, save settings, dan reset settings menunggu request selesai; state draf tetap terbuka bila persisten gagal atau konflik.
  - **Settings versioning**: Frontend GET/PUT settings membaca dan meneruskan `x-settings-version`; backend memakai optimistic compare-and-swap pada `user_settings.updated_at`. Jika versi yang dikirim stale, respons `409 SETTINGS_CONFLICT` minta user memuat ulang/sinkronisasi lalu retry.
  - **Global quick-template versioning**: GET settings juga mengembalikan `x-ketik-templates-version`. Admin menyimpan perubahan template melalui `PUT /api/v1/ketik/templates` dengan optimistic compare-and-swap pada singleton `ketik_global_settings.updated_at`; versi stale menghasilkan `409 SETTINGS_CONFLICT`.
  - **Template ownership**: Migration `20260910120000_ketik_global_quick_templates.sql` menyalin daftar template dari admin pertama yang memiliki settings ke singleton global. Row `user_settings` lama tidak dihapus; `PUT /api/v1/ketik/settings` menyimpan `personalQuickTemplates` milik user, dan GET menggabungkan template standar global dengan template pribadi. Konflik shortcut standar ditolak/diabaikan agar user tidak dapat menimpa template global.
  - **NIK dan email konsumen**: Identitas sesi diambil utuh dari 150 konsumen latihan (`packages/types/src/ketik-consumer-pool.ts`, dibangkitkan `scripts/generate-ketik-consumer-pool.mjs`; NIK berakhiran `0000`, email `@gmail.com`), kecuali field yang diisi di Pengaturan → Identitas. Trainer boleh mengisi NIK/email salah format atau domisili belum spesifik (provinsi, "Jakarta"); Pengaturan hanya memberi catatan netral. Agen melihat data apa adanya di panel Data konsumen. Konsumen AI tidak menyebut NIK/email sebelum diminta dan, saat dikonfirmasi, menolak atau memberi koreksi deterministik dari server. Telaah menilai konfirmasi minimal satu kali (`education.verification`; Probing −20 sekali per sesi bila belum dikonfirmasi). Sesi sebelum fitur ini (tanpa NIK) tidak dikenai aturan verifikasi. Lihat `plans/markdown/ketik-consumer-nik-email.md`.
  - **Penugasan dan salinan pribadi**: Trainer/admin dapat menyalin skenario, karakter, model, durasi, dan pacing dari konfigurasi akunnya ke salinan pribadi agen/leader melalui `/api/v1/ketik/assignments`. Agen/leader tetap mengedit settings sendiri; sumber trainer tidak berubah dan perubahan sumber tidak disinkronkan otomatis. Identitas/template pribadi dan settings modul lain dipertahankan. Tiga versi mencegah overwrite perubahan terbaru. Menu Penugasan trainer/admin memilih akun agen/leader aktif, memuat sumber/versi, dan meminta retry eksplisit setelah konflik. Agen/leader tanpa assignment atau gagal lookup tidak dapat mulai, tetapi tetap dapat membuka Pengaturan pribadi.
  - **Sesi server**: Start hanya mengirim request UUID dan pilihan subjek. Backend memilih serta membekukan skenario/identitas/model/durasi. Setiap kiriman agen langsung dipersist secara idempoten melalui `POST /sessions/:id/messages` dengan `expectedAgentVersion`; browser hanya memperingatkan unload selama append lokal belum diakui. Setelah quiet/read window, `POST /sessions/:id/respond` meminta satu balasan atas seluruh konteks durable. Kiriman baru tetap dapat dipersist saat AI berjalan; hasil AI stale dibuang dan diulang maksimal satu kali dengan konteks terbaru. Perubahan kedua saat retry membuat hasil tetap dibuang dan browser menjadwalkan response request baru. Kedua panggilan provider tetap tercatat sebagai usage. Endpoint `/turns` lama dipertahankan sementara untuk kompatibilitas. Expiry menutup composer tanpa pesan konsumen palsu.
  - **Finalisasi server**: Finish hanya mengirim `{}` ke ID sesi. Transkrip dipindahkan atomik ke history, tidak ditelaah otomatis, dan tetap ada bila publish history gagal. POST generate/history lama selalu 410. Row baru provenance `server_v1`; legacy dipertahankan dengan penanda transkrip belum terverifikasi server di tahap Telaah.
  - **Settings fail-closed**: Selama pengaturan server dimuat atau gagal dimuat, Mulai simulasi dan Pengaturan dinonaktifkan. Kegagalan tampil dengan tombol "Coba muat pengaturan"; retry tidak memulai chat atau menimpa draft. Backup `localStorage` per user (`ketik_settings_backup:<userId>`) masih ditulis setelah GET/save berhasil, tetapi tidak dipakai sebagai fallback otomatis untuk memulai sesi. Kegagalan storage/quota tetap diabaikan; server sumber kebenaran.
  - **CORS exposure**: CORS API mengekspos `x-settings-version` dan `x-ketik-templates-version` agar browser dapat membaca versi terbaru untuk masing-masing resource.
  - **Provider fallback**: Review AI memakai `KETIK_REVIEW_MODELS` di `apps/api/src/lib/ai-models.ts`, di-resolve melalui registry model: primary Gemini (`gemini-3.8-flash`), satu fallback OpenAI Responses API (`gpt-5.4-mini`). Perilaku model dan pencatatan usage tidak berubah.
  - **Role restriction saat ini**: Hanya `admin`/`trainer` dapat memicu analisis AI; role lain melihat tombol disabled dengan pesan akses. Fondasi penugasan belum mengubah gate ini.
  - **Sanitizer safety**: Structured JSON response tidak disanitasi sebelum parsing. Sanitasi hanya diterapkan ke field string setelah parse untuk mencegah corrupt JSON.
  - **Public errors**: Route KETIK memakai kode/copy Indonesia dari `KETIK_ERROR_MESSAGES` di shared types. Detail provider/database tidak dikirim melalui `error.message`, hasil review/worker `data.error`, atau polling `errorMessage`; konflik settings dan validasi terkurasi tetap spesifik. Kegagalan lookup pada jalur settings/review/worker yang diperbaiki menghasilkan 500, bukan 404 sesi hilang atau worker `no_jobs`; daftar/detail/summary riwayat memakai error eksplisit, tanpa fallback database menjadi sukses kosong. Operasi sesi memakai `KETIK_SESSION_ERRORS`; chat menampilkan error/retry tanpa menambah pesan sistem palsu atau mencetak stack provider.
  - **Legacy model normalization**: Model lama dari OpenRouter/DeepSeek dinormalisasi ke model direct yang tersedia saat settings dibaca, jadi UI lama tetap terbuka tanpa badge baru.
  - **Riwayat penuh**: GET `/ketik/history` mengembalikan `{items,nextCursor,total,counts,reviewedCount,averageScore}` tanpa transkrip; limit 1–100, cursor terikat search/status, timestamp/id descending. Search skenario/konsumen/peserta dan status dilakukan server. GET `/ketik/history/:id` memakai scope telaah (self/admin/trainer assignment) dan memuat transkrip serta skor sesi reviewed sebelum tanggalnya, sehingga deep-link sesi lama tetap bekerja; kegagalan mempertahankan URL dan menawarkan retry. GET `/ketik/history/summary` menghitung bulan WIB/processing pada seluruh scope dan rata-rata/fokus lima reviewed terakhir. CSV memuat seluruh hasil filter secara bertahap (100/request, maksimum 10.000); progress/error terlihat dan tidak mengunduh hasil parsial. Ekspor bukan snapshot transaksi lintas request.
  - **Review lifecycle**: POST `/ketik/review` hanya enqueue idempoten manual, HTTP 202 queued/processing. Worker persisten serial memakai tiga attempt maksimum dengan lease/token yang memagari worker lama; tidak ada provider call di route HTTP. Review/typos/skor/status dipublikasikan atomik. Hasil lama tetap completed selama rerun, dan kegagalan job menghasilkan `previousKept=true` pada polling. UI membedakan antrean, AI berjalan, gagal poll, retry, dan hasil; tidak memakai timeout browser 120s atau persen buatan. GET `/ketik/worker` retired 410. Aktivasi worker tetap opt-in dan memerlukan health sehat sebelum traffic enqueue-only.
  - **JSON extraction**: Parser review menggunakan `extractJsonObjectText()` untuk extrak JSON object dari output AI. Menangani plain JSON, markdown-fenced `json ... `, dan JSON dengan teks di sekitar. Tanpa ini, output fenced dari provider apa pun bisa menyebabkan parse error walaupun konten JSON-nya valid.
  - **Error messaging**: Polling status (`GET /ketik/review/status/:id`) mengembalikan `errorMessage` dengan teks manusiawi (Indonesia) jika status `failed`. Frontend menampilkan status gagal di tahap Telaah dengan teks manusiawi sendiri. Job-level `error_message` (untuk log teknis) tidak diekspos langsung ke UI.
  - **Send-while-loading guardrail**: Consumer/AI typing atau generation-in-flight tidak boleh menonaktifkan textarea, tombol Send, atau Enter. Satu-satunya guard pengiriman adalah input kosong, batas karakter, fase sesi tidak aktif/expired, atau batas antrean append lokal. Browser menampilkan bubble segera, lalu append server berjalan terpisah dari response AI; fencing `agent_version` dan response lease menjadi authority untuk discard-and-retry, bukan timeout/latest-wins lokal.
  - **Evaluasi Edukatif**: Review KETIK menghasilkan lapisan edukasi di atas skor deterministik. AI hanya memberi narasi `diagnosis`/`howToFix`/`exampleRewrite` per dimensi; backend menentukan `label`, `score`, `verdict` (threshold 90/75/60), dan `priorityRank: 1..5` (sort skor ASC + urutan dimensi tetap) di `buildKetikEducation()`. Fallback rule-based (`KETIK_EDUCATION_FALLBACK` per score band critical <60 / medium 60-74 / good ≥75) dipakai bila AI tidak mengirim narasi atau untuk histori lama — tanpa rerun AI. Hasil persist di kolom `ketik_session_reviews.education JSONB` (nullable, migration `20260823000000`) termasuk `typosEnriched`. Semua string nested AI disanitasi via `sanitizeKetikEducation()`. Endpoint monitoring `GET /api/ai/monitoring/history/ketik/:id/review` memetakan `education` dengan fallback dari skor tersimpan. UI: tahap Telaah (`KetikReviewStage`) menampilkan aspek di bawah 75 di tab "Perbaiki dulu" beserta contoh rewrite; halaman detail sesi Monitoring (`components/session/KetikSession.tsx`) menampilkan "Prioritas perbaikan" (top-3 `priorityRank`) + "Cara memperbaiki per aspek" dengan contoh rewrite.

## 3. PDKT (Paham Dulu Kasih Tanggapan)

Workspace untuk latihan korespondensi email yang terstandarisasi dengan sistem persistent mailbox.

- **Fungsi**: Simulasi penulisan email balasan untuk keluhan atau pertanyaan pelanggan.
- **Routes**: `/pdkt`, `/pdkt/history`; `/pdkt/simulation` mengarahkan ulang ke `/pdkt`.
- **Akses**: Trainer, QA, Admin, Leader, dan Agent. Agent dan Leader dapat mengakses simulasi PDKT.
- **Fitur Utama**:
  - **Halaman awal**: Hero "Pahami keluhannya. Balas dengan tepat." dengan menu Riwayat, Pemakaian AI (lencana biaya sesi terakhir), dan Pengaturan; ilustrasi tiga tahap Pahami → Tanggapi → Telaah (dekoratif, bisa dijeda, statis saat reduced-motion). Di bawahnya: **Progres latihan** (email `open` di kotak masuk, rata-rata skor 5 sesi terakhir yang ditelaah, sesi yang sedang ditelaah), **Belum dibalas** (maks. 3 email terlama; klik langsung membuka email itu tanpa pemilih peserta), **Fokus berikutnya** (aspek dengan rata-rata terendah), dan **Hasil telaah terbaru**. Semua angka dihitung dari `GET /pdkt/history` dan daftar ringan `GET /pdkt/mailbox`; tiap bagian punya keadaan memuat, kosong, dan gagal + "Coba lagi".
  - **Pengaturan PDKT**: Menu Skenario (jumlah aktif), Karakter konsumen, Identitas konsumen, dan Gaya & AI (gaya tulisan, model AI, sakelar Gambar lampiran). Daftar skenario memakai sakelar aktif, label arah balasan, cara pembuatan email (Dibuat AI / Tulis sendiri), pencarian, dan filter kategori. Footer menampilkan "Belum disimpan" saat ada perubahan.
  - **Ruang kerja tiga tahap**: Tahap mengikuti email terpilih.
    - **Pahami** (email `open` atau email `replied` tanpa membuka Telaah): kotak masuk dengan tombol Baru, menu lainnya (Riwayat, Pengaturan, Pilih beberapa), pencarian, dan filter Semua / Belum dibalas · N / Dibalas. Tiap baris menampilkan status: belum dibalas, sedang dinilai, gagal, atau Dibalas + skor. Panel baca hanya menampilkan email konsumen, bukan balasan agent atau hasil penilaian; data peserta dan pelaksana ada di header. Email dibalas menyediakan tombol "Lihat telaah" dan tahap "Telaah" yang bisa diklik, dengan status singkat tanpa angka skor di panel baca.
    - **Tanggapi** (editor dibuka): layar fokus tanpa daftar, berisi email konsumen dan editor "Balasan Anda" dengan hitungan kata. Draf disimpan per email di perangkat, termasuk saat kembali ke kotak masuk. Kirim selalu lewat konfirmasi "Kirim balasan sekarang?".
    - **Telaah** (email `replied`, dibuka secara eksplisit atau dari sesi Riwayat/hasil terbaru): layar fokus berisi Ringkasan skor (predikat, "Perbaiki ini dulu" dari action item prioritas 1, langkah berikutnya, kesesuaian kunci jawaban, lama pengerjaan) dan Rincian skor (aspek < 75 diberi "Perlu perbaikan"; alasan penilaian beserta kutipan balasan dan saran latihan ditampilkan pada semua skor bila tersedia). Alasan berbukti dan saran latihan diberi label terpisah; hasil lama/tidak lengkap menyatakan bahwa alasan dengan kutipan belum tersedia dan menawarkan telaah ulang. Ada juga Balasan Anda dengan catatan bernomor, Yang perlu diperbaiki, Temuan lain, Catatan AI, serta contoh balasan dan email konsumen yang bisa dibuka-tutup.
    - **Latihan lagi**: membuat email baru dengan peserta dari snapshot email yang ditelaah, termasuk sesi dari Riwayat. Skenario sesi dipakai bila masih aktif; bila tidak, tombol membuka pemilih skenario dengan peserta yang sama. Untuk role dengan pemilih peserta (trainer/admin), peserta terhapus (`participantId` null) atau atribusi tidak tercatat membuat tombol nonaktif dengan penjelasan. Agent/role tanpa pemilih peserta selalu membuat latihan ulang atas nama dirinya sendiri (`self`), termasuk email legacy tanpa atribusi dan jalur pemilih skenario. Email baru dari sidebar tetap memakai peserta ruang kerja.
    - **Navigasi dan pemulihan**: ruang kerja memakai `/pdkt?ruang=1&email=<mailboxId>`; membuka email menambah history browser, Back dari detail kembali ke daftar. Membuka Telaah menambah `&tahap=telaah` sebagai entri history baru: Back kembali ke email yang sama dan refresh mempertahankan layar Pahami/Telaah. Parameter Telaah diabaikan untuk email terbuka. Tahap Pahami di header Telaah kembali ke panel baca; untuk replay tanpa mailbox, tahap ini tidak bisa diklik. Berpindah Pahami/Telaah pada email yang sama mempertahankan `dari=riwayat`, sehingga tombol "Riwayat" tetap ada. Tanggapi kembali ke Pahami dengan draf lokal tetap tersimpan; tombol header berlabel "Kembali ke email". Sesi Riwayat memakai `sesi=<historyId>&ruang=1&dari=riwayat`, tetap tersedia saat refresh, dan header Telaah menyediakan "Riwayat". Replay sintetis memakai `sesi`, tanpa ID mailbox palsu di URL. Tombol ke landing menggunakan navigasi eksplisit `/pdkt`, sementara Back browser mengikuti history. Pilihan peserta untuk email baru disimpan di `sessionStorage` per akun (`pdkt_subject_<userId>`), dengan fallback `self` bila storage rusak/terblokir.

Recipient conflict cap diterapkan sesudahnya; feedback mencatat cap hanya jika score atau dimensi arah penerima benar-benar berubah.

Prompt meminta penjelasan pada semua skor; `buildPdktEdu()` hanya mempertahankan dimensi kanonik dengan alasan/kutipan tidak kosong, berbatas, dan kutipan yang ditemukan dalam balasan agen. "Email konsumen" menampilkan tanda A–E hijau/amber/merah dan daftar status tertulis "Terjawab", "Sebagian", "Belum terjawab"; tanda dan daftar saling memindahkan fokus. Huruf yang sama di balasan tertaut ke poin tanpa menambah warna latar. Kutipan tidak ditemukan tetap tampil di daftar; riwayat tanpa field baru tidak mendapat daftar atau telaah ulang otomatis. Referensi tidak masuk prompt generasi email atau proyeksi data simulasi; snapshot retry hanya dikirim dalam token terenkripsi, dan proyeksi pemulihan tidak memuat teks referensi. ## 4. TELEFUN (Telephone Fun)

Modul simulasi komunikasi suara untuk melatih intonasi dan kecepatan respon telepon.

- **Fungsi**: Mempersiapkan peserta untuk menangani panggilan telepon melalui simulasi suara berbasis Gemini Live.
- **Status provider**: Telefun model selection dan start flow Gemini-only. GPT/OpenAI Realtime Telefun telah concluded/permanently disabled untuk semua user; tidak ada OpenAI card, readiness, capability fetch, WebRTC POST, sideband, atau scoring baru. History, recording, feedback, usage, dan historical realtime pricing tetap readable; pricing historical read-only. Owner-bound DELETE cleanup tetap tersedia hanya untuk historical WebRTC call yang sudah terikat.
- **Batas OpenAI text**: Fallback/direct OpenAI text yang didokumentasikan untuk KETIK atau PDKT adalah operasi API terpisah. Itu tidak membuat model, transport, pricing realtime, atau provider Telefun OpenAI dapat dipilih.
- **Routes**: `/telefun` (landing + layar panggilan; tahap Telaah di `/telefun?sesi=<id>&tahap=telaah`), `/telefun/history` (tabel riwayat), `/telefun/replay/$id` (alamat lama, dialihkan ke tahap Telaah)
- **Fitur Utama**:
  - **Live Voice Interface**: Dialog "Siapa yang berlatih?" memuat cek mikrofon dengan meter level; "Mulai panggilan" baru aktif setelah izin mikrofon diberikan. Panggilan dimulai dari ringtone lalu koneksi WebSocket. Layar panggilan bergaya softphone: kepala tipis (Panggilan masuk, peserta, lama panggilan tanpa hitung mundur), data penelepon besar di tengah (nama, nomor telepon, kota), satu baris status, meter mikrofon tipis dengan pesan "Suara Anda tidak terdeteksi" setelah beberapa detik senyap, dan tombol Tahan, Bisukan, Akhiri. "Akhiri" membuka konfirmasi aplikasi; penutupan saat durasi habis tetap otomatis.
  - **Hold & Mute**: User bisa mute mikrofon dan menahan panggilan. Hold memiliki batas layanan (pertama 1 menit, berikutnya 3 menit) yang tidak memutus panggilan. UI menampilkan pita hold di bawah kepala layar: lama ditahan dibanding batas, peringatan 10 detik terakhir, dan "Hold melewati batas" (+MM.SS) setelah batas. Durasi hold dihitung dari timestamp, bukan tick timer. Metrics hold tersimpan di `session_metrics.hold` (intervals, durasi, exceeded count). Penilaian Manajemen Hold: N/A (tidak digunakan), Baik (semua ≤ batas), atau Kurang (ada yang melebihi batas). AI tidak menilai hold — policy aplikasi menentukan hasil secara deterministik.
  - **Recording & History**: Rekaman browser disimpan ke local history dan `telefun_history`. Saat MUTE atau HOLD aktif, seluruh microphone audio track dinonaktifkan untuk capture sehingga `full_call.webm` dan `agent_only.webm` tetap memiliki timeline yang utuh tetapi periode tersebut berisi silence; `MediaRecorder` tidak dihentikan atau di-restart.
  - **Telaah**: Setelah panggilan diakhiri, rekaman disimpan lalu halaman masuk ke tahap Telaah. Kiri: pemutar rekaman berbentuk gelombang dari rekaman itu sendiri dengan penanda data nyata (posisi putar, jeda hold dari `session_metrics.hold`, nomor catatan trainer yang bisa diklik) dan transkrip bertanda waktu; waktu baris adalah awal giliran bicara yang dibaca di browser dari rekaman gabungan + rekaman agen saja (waktu tercatat server tiba sesudah orangnya bicara), klik waktu memutar rekaman dari sana, label tanda kutipan membuka butirnya di panel hasil, dan kata pengisi disorot hanya bila teksnya ada di kalimat agen. Kanan: skor suara 0–10 satu desimal, enam aspek dengan angka mentah (kata/menit, jumlah kata pengisi, nada dominan, hold), lalu tab Perbaiki dulu, Sudah baik, Penjelasan skor, Catatan trainer (`ReplayAnnotator`), Pertanyaan konsumen, Kalimat agen, dan Profil (diagram spider skor aspek 0–10 berlabel Indonesia dengan cincin skala berangka, tanpa zona berwarna). Sebelum skor ada, panel mengikuti `scoring_status` apa adanya: menunggu/sedang dianalisis (Periksa status), gagal (Analisis ulang), belum dianalisis (Mulai analisis), atau rekaman tidak tersimpan. Popup review dan halaman replay lama sudah dihapus.
  - **Bukti isi dan penjelasan suara**: Tab Perbaiki dulu/Sudah baik mengelompokkan `contentReview.agentNotes` menurut verdict `fix`/`good`, dengan indeks catatan asli; skor suara tinggi tidak menghilangkan koreksi isi. Klik nama aspek membuka Penjelasan skor yang menampilkan semua aspek, feedback, latihan dan contoh yang tersedia pada skor berapa pun. Riwayat tanpa telaah isi menyatakan belum tersedia, sementara feedback suara tetap dapat dibaca. Label kutipan transkrip dapat dipakai berulang untuk kembali memfokuskan catatan yang sama; tombol kutipan pada catatan kembali ke baris transkrip, dengan scroll yang menghormati reduced motion. Alur ini dicakup `apps/web/e2e/telefun-flow.spec.ts`.
  - **Landing**: Hero dengan satu aksi utama, menu kecil (Riwayat, popover Pemakaian AI, Pengaturan), dan demo panggilan → telaah yang bisa dijeda. Di bawahnya progres (panggilan bulan ini, rata-rata 5 skor terakhir, sedang dianalisis), Perlu tindak lanjut (analisis gagal, rekaman tidak tersimpan), Fokus berikutnya (aspek terendah), dan Hasil telaah terbaru. Semua angka dihitung dari riwayat yang dimuat.
  - **Riwayat**: Halaman `/telefun/history` berupa tabel dengan filter status analisis, pencarian, unduh CSV, dan menu per baris (Unduh rekaman, Hapus). Hapus dan Hapus semua memakai dialog konfirmasi aplikasi. Penanda eksplisit tampil bila record peserta sudah tidak tersedia.
  - **Voice Assessment**: Analisis otomatis kualitas suara agen.
  - **Realistic Mode**: Mode realistik dengan hold consent, rude hold penalty, dan WPM analysis.
  - **Simulation Challenges**: Skenario tantangan simulasi (max 3) yang diintegrasikan ke dalam Gemini Live system prompt. Tantangan didefinisikan di settings dan diterapkan secara dinamis selama sesi.
  - **Expanded Voices**: Katalog 30 voice Gemini Live/TTS dengan mapping gender aplikasi (14 female, 16 male), gender consistency guards, dan default voice `Kore`.
  - **Monitoring detail**: `/monitoring` memakai `parseVoiceQualityAssessment`, `telefun_coaching_summary.recommendations` yang runtime-normalized, `HoldAssessmentCard`, dan metrik sumber apa adanya (score, WPM, intonasi, artikulasi, filler, tone); row `telefun_history` canonical menang atas row legacy `results` dengan ID yang sama, sedangkan legacy-only tetap incomplete dan recording path hanya disigning dari path owned yang aman.
  - **Maintenance Warning Gate**: Entry to Telefun dari sidebar, dashboard card, atau URL direct `/telefun` dilindungi oleh role-based access gate. User dengan role admin/trainer di-auto-grant akses langsung tanpa modal warning. User dengan role lain (leader, agent) melihat modal "Akses Terbatas" dengan pesan "Modul Telefun hanya dapat diakses oleh Trainer" dan hanya bisa kembali ke dashboard. Status akses di-reset otomatis saat meninggalkan modul Telefun.
  - **Gemini Live JSON Protocol**: Menggunakan format JSON terstruktur untuk setup dan pengiriman chunk audio base64 (MIME `audio/pcm;rate=16000`), menggantikan transfer data binary mentah yang rentan force close. Output suara dari Gemini Live didecode dari JSON inline base64 PCM secara real-time pada sample rate output (default 24 kHz).
  - **Setup Complete Gating**: Pengiriman audio microphone ke WebSocket ditahan (gated) di sisi client dan proxy sampai pesan `setupComplete` dikonfirmasi oleh Gemini.
  - **Deterministic Finalization**: Proses penyimpanan sesi diatur secara deterministik (Upload Rekaman → Patch Metadata → Finalize Path → Request Scoring → Patch Score & Feedback) untuk memastikan analisis suara tidak gagal akibat data audio belum tersedia. Feedback disimpan di kolom `feedback` terpisah secara konsisten. Status scoring dibedakan menjadi `succeeded`, `failed` (scoring sempat dicoba lalu error), dan `skipped` (rekaman agen tidak tersedia sehingga scoring tidak dicoba).
  - **WebSocket Close-Code Mapping**: Menampilkan pesan error terperinci untuk error status koneksi (seperti token login kadaluarsa `4001`, origin ditolak `4003`, Gemini API error `1011`, atau network terputus `1006`). Close normal dari user (code `1000`) tidak ditampilkan sebagai error; close tanpa status `1005` dipetakan secara khusus sebagai indikasi proxy/network/upstream.
  - **Auto Hangup & Time Cues**: Durasi panggilan dibatasi sesuai `maxCallDuration` dengan reminder audio/text cue bertahap (2 menit, 1 menit, 30 detik, 20 detik). App timer adalah satu-satunya otoritas timeout; AI tidak diminta mengestimasi waktu sendiri.
  - **Self-Close Guard**: Prompt Telefun melarang konsumen menutup sendiri hanya karena solusi awal, arahan website/link/form laporan, estimasi SLA, nomor referensi, atau penjelasan agen sudah terdengar cukup. Konsumen tetap kooperatif, tetapi harus lanjut bertanya/konfirmasi sampai aplikasi mengirim cue penutup.
  - **Akses**: Modul Telefun hanya untuk `admin` dan `trainer`. Leader dan Agent tidak diizinkan mengakses modul ini — akan mendapat modal "Akses Terbatas" dan redirect ke dashboard.
  - **Catatan Teknis**:
  - **Evaluasi Edukatif (deterministik)**: `TELEFUN_VOICE_ASSESSMENT_JSON_SCHEMA` tidak diperluas untuk coaching — AI tetap hanya menghasilkan 5 aspek kanonik. Semua coaching diturunkan backend: `improvementTip` (`generateImprovementTip`), `drill` latihan per metrik (`generateDrill`, rule-based parametrik target WPM/filler), `examplePhrase` per metrik (`TELEFUN_EXAMPLE_PHRASES`), `nextSteps`/`drill` hold rule-based dengan batas dari `TELEFUN_FIRST_HOLD_LIMIT_MS`/`TELEFUN_SUBSEQUENT_HOLD_LIMIT_MS`, serta `overallNextSteps` (top-3 dari `improvementPriorities`). Profil komunikasi membawa `coachingVersion: 1`; histori lama tanpa drill/examplePhrase otomatis di-rebuild oleh `enrichAssessmentWithCommunicationProfile()` tanpa rerun AI. UI: tab "Penjelasan skor" di tahap Telaah menampilkan feedback, latihan (tip atau drill), dan examplePhrase per aspek tanpa ambang skor; tab "Perbaiki dulu" menampilkan koreksi ucapan dan langkah latihan berikutnya; di Monitoring, `VoiceMetricCards` dan `HoldAssessmentCard` tetap menampilkannya.
  - **Gemini Live Session Management**: Untuk sesi panjang (>5 menit), setup menyertakan `contextWindowCompression` dan `sessionResumption`. Proxy server mendeteksi `goAway.timeLeft` dan `sessionResumptionUpdate.newHandle` untuk reconnect proaktif dengan setup caching.
  - **Server Reconnect Lifecycle**: Saat koneksi Gemini putus non-1000, proxy reconnect dengan backoff, re-send cached setup, menyertakan session handle jika ada, dan hanya flush audio setelah `setupComplete`. Client mendapat status "Menyambung ulang..." dan "Tersambung".
  - **Duration Audit Source**: Durasi final sesi memakai elapsed timestamp dari `session_metrics.sessionDurationMs` saat tersedia, sehingga reconnect status seperti "Menyambung ulang..." tidak membuat durasi audit lebih pendek dari runtime aktual.
  - **Keepalive**: Server mengirim ping berkala (30 detik) ke client dan Gemini untuk mengurangi idle disconnect.
  - **AudioWorklet**: Browser modern menggunakan AudioWorklet (`/audio-input-processor.js`) untuk pemrosesan mikrofon. Browser lama atau jika load gagal, fallback ke ScriptProcessorNode. Tidak ada warning deprecasi pada browser modern.
  - **Recording Path RLS Security**: Mengunggah file rekaman ke storage Supabase memakai struktur direktori terproteksi RLS `<user_id>/<session_id>/(full_call|agent_only).webm` dan divalidasi ketat oleh API backend.
  - **Recording Playback Access**: File rekaman di bucket `telefun-recordings` tetap private. Browser tidak boleh memakai `recording_path` mentah sebagai URL audio; backend membuat signed URL sementara. Pemilik sesi dapat memutar rekamannya sendiri dari modul Telefun, sedangkan akses lintas-user untuk mendengar rekaman hanya diberikan kepada `admin` dan `trainer`. Monitoring Telefun detail juga memakai signed URL yang sama dan tidak memberikan URL pemutaran untuk role lain.
  - **Playback Queue Cleanup**: Setiap `AudioBufferSourceNode` yang dibuat oleh `playPcm()` dilacak dalam `activeSources: Set<AudioBufferSourceNode>`. Saat `serverContent.interrupted`, `setHold(true)`, atau turn baru tiba setelah `turnComplete` lama, seluruh source aktif dihentikan dan antrian dibersihkan untuk mencegah overlap audio. Chunk lanjutan dalam turn yang sama tetap diantrikan normal. `turnComplete` tidak langsung mengakhiri `isAiSpeaking` - ditunda sampai source terakhir selesai natural (via `onended`).
  - **Mute/Hold Capture Gate**: `LiveSession` menerapkan `track.enabled = !isMuted && !isHeld` pada semua microphone audio track setelah `getUserMedia()` dan setiap kali `setMute()` atau `setHold()` mengubah state. Gate capture ini terpisah dari gate pengiriman audio ke Gemini dan dari pembersihan playback AI; recorder tetap berjalan agar timeline rekaman tidak berlubang.
  - **First-Message WebSocket Authentication**: Browser hanya membaca `auth_token` satu kali saat memulai panggilan, meneruskannya melalui `PhoneInterface` ke `LiveSession`, lalu mengirim frame pertama `{ type: "authenticate", token, sessionId? }`. URL WebSocket hanya berisi path `/ws`; credential dan session ID tidak masuk query string atau log target.
  - **Pre-Auth Gate**: Standalone proxy memvalidasi origin/path, menunggu auth maksimal 10 detik, menolak frame non-auth, auth paralel, dan auth duplikat, lalu memverifikasi JWT serta ownership session sebelum mengirim `auth_ok` dan membuka koneksi Gemini. Perubahan client dan server harus dideploy bersamaan.
  - **Local History Recovery**: JSON `telefun_history` yang malformed atau bukan array tidak menghambat pemuatan history server. UI menampilkan warning aman tanpa menyalin payload lokal ke toast/log dan tanpa menghapus data lokal.
  - **Catatan Teknis**: Sesi live default memakai model transport `gemini-3.8-live`; model `gemini-3.1-flash-live-preview` dan `gemini-3.0-flash-live-preview` tetap tersedia sebagai pilihan eksplisit (menggunakan parameter `telefunModelId`). Telefun proxy server di `apps/telefun/` memvalidasi origin/JWT, memverifikasi kepemilikan session ID, dan meneruskan JSON secara aman ke Gemini Live API. Sesi WebSocket melekat langsung ke session row yang dibuat API frontend untuk mencegah data duplikat. Close code 1005 dari browser dipetakan sebagai sinyal diagnostik jaringan, bukan kesalahan pengguna. Proxy menutup upstream dengan code/reason eksplisit pada client close/error (1000/1011).

## 5. KTP / Profiler (Kotak Tool Profil)

Sistem manajemen database terstruktur untuk peserta training dan agen aktif.

- **Fungsi**: Penyimpanan terpusat data diri, riwayat training, dan penugasan tim.
- **Routes**: `/profiler` (workspace, `?batch=&view=statistik|slide|ekspor&participant=`), `/profiler/table`, `/profiler/add`, `/profiler/import`, `/profiler/teams`. `/profiler/analytics`, `/profiler/slides`, `/profiler/export`, `/profiler/download`, dan `/preview/profiler-slides` hanya redirect ke tab workspace yang sesuai.
- **Fitur Utama**:
  - **Workspace (`/profiler`)**: Panel kiri adalah satu-satunya navigasi (pemilih tahun, pencarian, tim → batch dengan jumlah peserta, menu baris untuk tambah batch/duplikat/ubah nama/hapus; di layar sempit dibuka lewat tombol "Pilih batch"). Batch aktif disimpan di URL `?batch=` (tahan refresh/back; nama tak dikenal kembali ke ringkasan). Tanpa batch: daftar batch tahun aktif + widget ulang tahun global. Dengan batch: tab **Peserta** (daftar + pencarian, baris ulang tahun ≤7 hari), **Statistik** (distribusi jabatan/tim/gender/pendidikan, klik untuk daftar peserta), **Slide** (satu peserta per slide, simpan PNG/PDF, peserta aktif di `?participant=`), dan **Ekspor** (Excel/CSV/PPTX/PDF + orientasi). Ketiga tab memakai data peserta yang sudah dimuat workspace dan dimuat lazy; tab aktif ikut terbawa saat berpindah batch. **Tabel lengkap** tetap ke `/profiler/table`. Satu tombol "Tambah peserta" (pilih dari daftar, input manual, impor Excel). Mode hanya-baca (leader/qa) menyembunyikan semua aksi tulis.
  - **Table View**: Search, filter, dan edit data peserta dengan responsive grid layout (1-4 kolom) dan glassmorphism cards.
  - **Import**: Excel template generation dan upload.
  - **Teams**: Custom team management.
  - **Upcoming Birthdays**: Endpoint untuk menampilkan peserta yang berulang tahun dalam rentang waktu tertentu.
- **Catatan Teknis**: File peserta/foto memakai Supabase Storage bucket `profiler-foto`. Backend API di `/api/v1/profiler/` (18+ endpoints) menangani semua operasi CRUD. Reorder authorization dilindungi oleh service_role bypass dengan dedup/validity checks.

## 6. SIDAK (Sistem Informasi Data Analisis Kualitas)

Platform analytics kualitas untuk memantau performa agent secara mendalam.

- **Fungsi**: Mengolah data temuan QA menjadi wawasan yang dapat ditindaklanjuti melalui dashboard, ranking, input manual, dan laporan otomatis.
- **Routes**:
  - **Ringkasan** (`/sidak`): Beranda kerja berbasis data, bukan kartu menu. Kepala `h1 "SIDAK"` + baris cakupan + satu aksi utama per peran (admin/trainer `Input temuan`, leader `Lihat agen saya`). Bagian: **Kondisi periode terbaru** (rata-rata skor agen, agen diaudit, temuan, tiket bertemuan dari `periodMetrics` `GET /sidak/dashboard`, dibanding periode sebelumnya), **Perlu tindak lanjut** (agen `atRisk` dari `GET /sidak/agents`, skor terendah dulu; definisi sama dengan item Beranda "agen di bawah target"), **Parameter teratas** (tiga teratas Pareto), dan **Halaman SIDAK** (sub-halaman per kelompok kerja dari model navigasi, tersaring capability). Tiap bagian punya state memuat/kosong/gagal + `Coba lagi`; tidak ada forecast yang dipicu.
  - **Cakupan bersama**: layanan, tahun, rentang bulan, dan tim dibawa di query (`layanan`, `tahun`, `dari`, `sampai`, `tim`) dan di `sessionStorage` sehingga Ringkasan, Dashboard, Forecast, Ranking, Heatmap (tahun + layanan), dan Agen (tahun) memakai cakupan yang sama ketika berpindah halaman, termasuk lewat sidebar. Tautan lama Ranking (`service_type`, `year`) tetap diterima. Semua sub-halaman memakai `SidakPageHeader`.
  - **Dashboard** (`/sidak/dashboard`): Header menyatakan cakupan aktif (layanan · tim · rentang bulan tahun) di atas filter. Empat KPI tampil dalam satu strip berbagi garis (nilai, delta vs periode sebelumnya, keterangan; sparkline hanya pada layout lebar). **Ringkasan temuan** berisi tiga sorotan berdampingan: periode terbaru (perubahan jumlah, bukan tingkat), porsi temuan kritikal dengan denominator temuan berkategori dan bar komposisi, serta **Perkiraan temuan** (arah, perubahan, horizon, kepercayaan; tombol update dan tautan `/sidak/forecast`). Berikutnya Tren temuan (maks. dua seri, toggle garis proyeksi) berdampingan dengan Top 5 agen (tim, skor, jumlah temuan, penanda kritikal, tautan ranking), lalu **Parameter teratas** (Pareto sebagai bar horizontal dengan nama lengkap, jumlah, porsi, dan ringkasan fokus 80%) berdampingan dengan **Pola temuan mingguan** (distribusi temuan setahun penuh per hari dalam minggu Senin–Minggu dan tanggal puncak dari heatmap Agent, `tanggal_layanan`, hitung per parameter, tautan kalender lengkap; sengaja bukan grafik bulanan agar tidak menduplikasi Tren temuan). Grafik tujuh bar berlabel jumlah dengan hari tersibuk disorot mengisi sisa tinggi panel, diikuti statistik hari dengan temuan, rata-rata per hari aktif, serta porsi akhir pekan (Sabtu–Minggu); semua angka adalah volume, bukan tingkat temuan. Heatmap mengikuti tahun/layanan filter, tidak mengikuti filter tim/bulan, dan tetap dibatasi scope backend. State memuat, gagal/coba lagi, dan kosong tampil eksplisit. Tombol **Perbarui data** memuat ulang filter aktif dan kegagalan refresh tetap mempertahankan data terakhir.
  - **Forecast** (`/sidak/forecast`): Workbench analitik untuk proyeksi layanan dan lane agen (`improving`/`declining`/`stable`/`insufficient_data`) dengan service chart, filter parameter, dan proyeksi agent berbasis regresi linear. Filter membedakan `Periode data` dari `Periode proyeksi` 1–6 bulan. UI memakai bar filter satu blok, section flat `Tren layanan` (ringkasan proyeksi inline) lalu `Prioritas agen` (empat kelompok Membaik/Memburuk/Stabil/stagnan/Pantauan, status dari `components/sidak/forecast-status.ts`); row agent memprioritaskan skor/tren, metadata wrap-safe, serta lane desktop memakai max-height dan scroll internal saat daftar panjang.
  - **Input Temuan** (`/sidak/input`): Satu layar kerja (bukan wizard): `h1`, bar konteks Folder/Agen (combobox cari)/Periode/Layanan, ringkasan sesi satu baris (skor live dengan ambang target 95 dari `utils/sidakScoreStatus.ts`, jumlah temuan, jumlah tiket), lalu daftar temuan per tiket. Entry manual + Excel upload tetap. Konteks disinkronkan ke query `folder`, `agent_id`, `period_id`, `service` via `history.replaceState`. Konfirmasi no. tiket kosong dan temuan/baris duplikat memakai `ConfirmDialog` (bukan `window.confirm`); status sukses menyebut jumlah tersimpan dan menautkan ke detail agen. `POST /sidak/temuan/batch` bersifat all-or-nothing: item invalid apa pun → **422** `INVALID_INDICATORS` (`details` = daftar item invalid, tidak ada baris tersimpan); semua item duplikat → **200** `inserted: 0`; ada baris baru → **201**. Bila versi aturan efektif ada, hanya master yang dipetakan versi itu yang diterima. Parameter lama tanpa master tampil nonaktif berlabel "Belum terhubung" di dropdown dan menjadi error baris saat import Excel. **Sesi Tanpa Temuan** memakai parameter versi efektif (`rule_version_id` + `rule_indicator_id` terisi) dan menolak dengan pesan jelas bila versi masih memuat parameter tanpa master.
  - **Heatmap** (`/sidak/heatmap`): Kalender tahunan jumlah temuan ketidaksesuaian per hari, dengan dua mode yang membaca kolom tanggal berbeda — **Agent** memakai `tanggal_layanan` (kapan interaksi bermasalah terjadi), **QA** memakai `tanggal sampel` (kapan QA memeriksa/menetapkan temuan). Filter tahun, layanan, dan **satuan hitung** (Parameter = satu baris countable = satu temuan; Tiket = distinct `no_tiket` per hari, baris tanpa nomor tiket dihitung per baris). Bagian **Pola temuan ketidaksesuaian** dibuka dengan narasi singkat (total temuan dan jumlah hari bertemuan tahun aktif, tanggal puncak, serta hari dalam sepekan dan bulan dengan temuan terbanyak), lalu kartu: tanggal temuan terbanyak, tanggal temuan paling sedikit (di antara hari yang ada temuannya), hari terbanyak dalam sepekan, bulan terbanyak, hari dengan temuan, rata-rata harian, dan rentang temuan. Kartu ringkasan "Temuan tanpa tanggal" menghitung temuan semua tahun yang tanggalnya kosong sehingga tidak tampil di kalender. Narasinya menegaskan bahwa angka menunjukkan volume temuan, bukan tingkat ketidaksesuaian; perbandingan perlu mempertimbangkan jumlah layanan/audit dan banyaknya hari pada tiap periode. Legenda intensitas diturunkan dari sebaran data tahun aktif (kuartil hari bertemuan; bucket `0` selalu ada, ambang yang bertabrakan digabung) sehingga tidak ada bucket kosong di atas nilai maksimum dan warna tetap terbaca berapa pun volume temuannya. Akses admin/trainer (semua data) dan **leader (hanya agent dalam scope-nya)**; nama mode "QA" di dalam halaman tidak memberi hak akses ke role `qa`. Tab **Heatmap** yang sama juga tersedia di detail agent (`/sidak/agents/$id`).
  - **Ranking** (`/sidak/ranking`): Ranking prioritas temuan agent; rank 1 berarti defect terbanyak. Desktop menampilkan perubahan posisi di satu kolom, sedangkan mobile menampilkannya di bawah nama agar tidak ada informasi ganda.
  - **Settings** (`/sidak/settings`): Service weights configuration dengan versioned rules per service+periode. Parameter baru yang ditambahkan ke draft otomatis mendapat master `qa_indicators` sehingga langsung bisa dicatat setelah dipublikasikan dan ID-nya stabil di revisi berikutnya; parameter dengan identitas yang sama di satu versi ditolak (422).
  - **Periods** (`/sidak/periods`): Manajemen periode audit.
  - **Agents** (`/sidak/agents`): Direktori agent dengan pencarian nama/tim/batch, filter batch menggunakan satu selector semantik di seluruh breakpoint, toggle untuk menyertakan agen tambahan di luar daftar utama, serta kartu audit yang menampilkan identitas, skor, status, periode, dan perubahan. Grid responsif memakai 1 kolom di mobile, 2 di tablet, dan 3 di desktop; kartu tetap satu surface tanpa nested mini-card atau badge dekoratif. Mendukung skeleton loading, state kosong, retry saat API gagal, serta load-more dinamis dalam batch awal 24 agen.
  - **Agent Detail** (`/sidak/agents/$id`): Dua kolom. **Sidebar profil** (tanpa scroll internal; di desktop menempel hanya bila seluruh isinya muat di layar, selain itu ikut scroll halaman; blok atas di mobile) berisi foto 160px (96px mobile), nama, tim/batch/jabatan/masa kerja, aksi Input Audit / Unduh Laporan / Muat ulang, satu pemilih **Ganti agen** dengan pencarian nama/tim/batch (direktori `GET /sidak/agents`, dimuat saat dibuka), skor bulan terbaru, serta peringkat Tim Gabungan/Tim Leader dan forecast 3 bulan (konteks tahun+layanan). Kolom kanan: tab Ringkasan/Tren/Temuan/Heatmap/Simulasi → toolbar Tahun + Layanan (+ rentang bulan di Tren) → isi. - **Fitur Utama**:
  - **Versioned Rules**: Parameter penilaian per service+periode dengan versioning.
  - **Scoring Engine**: Perhitungan skor agent dengan weighted/counting mode, clean-session handling, phantom padding exclusion.
  - **Dashboard Summary Rollup**: Real-time computation dari data temuan mentah via scoring engine aplikasi.
  - **Forecast Agent**: Proyeksi skor, temuan, dan critical findings per agent dengan regresi linear; klasifikasi lane (improving/declining/stable). Snapshot persistence dengan SHA-256 fingerprinting dan 3-state lifecycle (missing/fresh/stale).
  - **Agent Audit Dossier**: Panel bulan terpilih dengan judul bulan, skor + status, Sesi/Temuan/Selisih (poin), lalu tiket pengurang terbesar dan akar masalah (pola utama + pola lain) berdampingan.
  - **Agent Comparison Table**: Benchmark temuan kumulatif agent terhadap rata-rata tim dan rata-rata service.
  - **Root Cause Diagnosis**: Rule-based clustering (8 klaster) dengan keyword matching dan ticket references. Target coverage: lainnya < 20%.
  - **Folder-Aware Filters**: Dashboard dan ranking dapat difilter berdasarkan folder/batch audit untuk scope yang lebih presisi, termasuk untuk leader scope.
  - **Phantom Padding**: Clean session (audit tanpa temuan real) tetap dihitung sebagai valid audit.
  - **Sesi Tanpa Temuan**: Trainer/admin dapat membuat 5 sesi phantom (nilai=3) ketika agent belum memiliki temuan buruk.
  - **Excel Upload**: Template generation, parsing, dan validasi untuk bulk input temuan.
  - **Rank Change Indicator**: Perubahan prioritas memakai `rankChange = previousRank - currentRank`. Nilai positif berarti prioritas naik menuju rank yang lebih kecil (defect lebih banyak), nilai negatif berarti prioritas turun, `0` berarti tetap, dan `null` berarti agent baru. Pada desktop status hanya muncul di kolom Perubahan posisi; pada mobile status dipindah ke bawah nama. Catatan berbagi peringkat ditampilkan terpisah dari status perubahan.
  - **Agent Ranking Semantics**: Ranking utama adalah prioritas temuan: rank 1 = defect terbanyak dan rank lebih besar = prioritas lebih rendah. Jumlah defect sama memakai competition ranking sehingga berbagi peringkat; tie-break nama hanya mengatur urutan baris, bukan rank bisnis. Ranking ditampilkan dalam konteks Tim Gabungan dan Tim Leader per tahun+layanan.
  - **KPI Delta**: Persentase kenaikan/penurunan di KPI Dashboard dengan unit yang disesuaikan (persentase relatif untuk count/ratio, poin persentase untuk metrik persen).
  - **Riwayat Simulasi**: Filter hanya berdasarkan atribusi `participant` yang cocok dengan `profiler_peserta.id`; detail memakai review Monitoring bersama dan tidak memicu AI. Filter audit tahun/bulan/layanan tidak mengubah daftar simulasi.
  - **Catatan Teknis**: Backend API di `/api/v1/sidak/` di-dekomposisi ke route handler (`apps/api/src/routes/sidak/{core,dashboard,forecast,temuan,rule-versions,reports,simulations}.ts`). Riwayat simulasi memakai `apps/api/src/services/sidak/agent-simulations.ts` dan scope `simulation-access.ts`; renderer detail tetap memakai komponen Monitoring bersama. Scoring engine di `apps/api/src/lib/scoring.ts`.

## 7. Atribusi Subjek Simulasi (KETIK/PDKT/Telefun/Monitoring)

- `user_id` tetap akun pelaksana/pemilik sesi; `simulation_subject_*` adalah atribusi peserta, bukan identitas konsumen.
- Request memakai satu properti `simulationSubject` (`self` | `participant` + UUID). Klien lama tanpa field dinormalisasi ke `self` pada write ingress; read null/absent selalu `unknown` (legacy: "Peserta tidak tercatat — sesi lama").

## 8. TNA — Training Needs Analysis (Fase 1)

- **Alur antarmuka:** `/tna` (filter layanan/periode/jumlah pembanding di URL, kandidat default dan toggle “Tampilkan semua parameter”) → `/tna/parameter` (drill-down + validasi) → `/tna/kebutuhan/$id` (snapshot validasi + susun rencana) → `/tna/rencana/$id` (edit draf, pratinjau, konfirmasi aktivasi/pembatalan, baseline beku, Ringkasan TNA).
- Entri TNA tersedia bagi admin/trainer di rail desktop dan drawer mobile, tanpa submenu atau tab mobile baru. Breadcrumb mengikuti halaman; leader/agent tidak melihat entri dan route guard menolak akses.
- Tingkat adalah temuan **per 100 sesi sampel**, bukan persentase tiket. Phantom-only tetap merupakan audit; tanpa audit menghasilkan tingkat/sebaran `null`, bukan nol. `scope=all` menampilkan parameter dengan baris audit termasuk nol temuan; bila periode tanpa audit, parameter berasal dari pembanding dan ditandai banner no-audit. “Data belum cukup” tidak ditampilkan untuk daftar kosong.
- State memuat/kosong/gagal + **Coba lagi** eksplisit; konflik 409 mengunci aksi hingga **Muat ulang**. Klaster berlabel **Dugaan otomatis**, bukan diagnosis tervalidasi. Tidak memakai AI, evaluasi Fase 2, pengelolaan katalog, atau akses leader.
- Akses API `/api/v1/tna/*` hanya admin/trainer melalui `tna.read` dan `tna.write`; leader/agent mendapat 403.
- Endpoint tersedia: `GET /programs` (katalog aktif), `GET /parameters`, `GET /parameters/detail`, `POST /needs`, `GET /needs`, dan `GET /needs/:id`. Daftar kebutuhan menerima filter `service_type`, `period_id`, dan `outcome`; detail mengembalikan `{ need, plans }`.
- Drill-down mengembalikan `{ metrics, affected_agents, clusters, sample_tickets, suggested_programs }`. Metrik memakai mesin TNA dan tiga bucket SIDAK; klaster memakai `deriveAgentRootCauses` tanpa registry baru, maksimal 5 klaster, 3 bukti per klaster, dan 10 contoh tiket.
- Create need menghitung ulang `validation_snapshot` dan `suggested_cluster_id` dari QA saat request. Angka, snapshot, dan identitas actor dari body diabaikan. Kebutuhan boleh dibuat untuk parameter bukan kandidat selama temuan > 0; nol temuan (termasuk tidak ada audit) ditolak dengan 422 `TNA_NO_FINDINGS`.
- Pembacaan memakai JWT pengguna/RLS. Mutasi lewat `services/tna/write-service.ts` → lima RPC TNA memakai backend service-role dengan actor dari autentikasi, kemudian `logActivity` (`module: tna`). Detail tabel, guard, dan trigger: [database](database.md#tna--training-needs-analysis-fase-1); kapabilitas dan batas service-role: [auth/RBAC](auth-rbac.md#tna--kapabilitas-dan-jalur-tulis-fase-1).
- Rencana tersedia lewat `POST/GET /plans`, `GET/PATCH /plans/:id`, `POST /plans/:id/activate`, dan `POST /plans/:id/cancel`. Daftar dapat difilter `status`. Seluruh mutasi lewat `write-service.ts` dan lima RPC `tna_*`; pembacaan kebutuhan, rencana, peserta, program, periode, serta QA tetap memakai JWT pengguna. Create/update/activate/cancel mencatat `logActivity`.
- Detail rencana mengembalikan `{ plan, participants, preview, participant_preview, narrative }`. Saat draft, kedua preview dihitung live dan kolom baseline di database tetap `NULL`. Saat aktivasi, server menghitung ulang metrik populasi dan temuan parameter bagi roster final, termasuk `validation_drift` terhadap snapshot kebutuhan; RPC membekukan baseline populasi/peserta. Detail aktif atau pembatalan setelah aktivasi membaca baseline tersimpan tanpa menghitung QA ulang.
- Aktivasi tanpa audit → 422 `TNA_BASELINE_NO_AUDIT`; audit dengan nol temuan → 422 `TNA_BASELINE_NO_FINDINGS`; kedua target tidak lebih baik → 422 `TNA_TARGET_NOT_BETTER`. Salah satu target yang lebih baik cukup. Peserta 1–200, unik, terlihat melalui RLS, dan bukan agent non-service; peserta invalid → 422. Need eskalasi dan program nonaktif → 422; rencana terbuka duplikat, versi basi, edit non-draft, atau transisi berkonflik → 409 dengan ajakan muat ulang. Snapshot/baseline dari body plan ditolak sebagai input tidak dikenal.
- Narasi `narrative.ts` mengikuti status tren D9, format angka Indonesia, label `Pratinjau:`, dan kalimat tanpa angka tingkat/sebaran untuk `no_audit`. Pembatalan draft belum punya baseline; detail menyatakan baseline belum dibekukan. Label layanan memakai label SIDAK, dan status rencana tampil sebagai Draf/Aktif/Evaluasi/Selesai/Dibatalkan. Kontrak lengkap: [rencana rev. 7](../plans/markdown/tna-phase-1.md).

## 9. TNA — Evaluasi pasca-training (Fase 2)

- **Alur:** rencana `aktif` → **Mulai evaluasi** saat jatuh tempo (pilih periode evaluasi) → `evaluasi` (pratinjau live, boleh ganti periode) → **Selesaikan** dengan kesimpulan + tindak lanjut → `selesai` (hasil beku). Rencana `aktif`/`evaluasi` dapat dibatalkan dengan alasan wajib 10–1000 karakter.
- **Jatuh tempo** memakai tanggal Asia/Jakarta: `GET /plans?due=1` mengembalikan rencana `aktif` dengan `evaluation_due_date` ≤ hari ini (WIB) plus semua rencana `evaluasi`; setiap item membawa `evaluation_due`. `/tna` menampilkannya di bagian **Perlu dievaluasi**. Server menolak mulai lebih awal dengan 422 `TNA_EVALUATION_NOT_DUE`.
- **Periode evaluasi** harus sesudah bulan berakhirnya pelatihan. Opsi (`evaluation_period_options`) diurutkan kronologis; default adalah periode pertama yang sudah diaudit. Periode tanpa audit boleh dipilih untuk pratinjau, tetapi rencana tidak bisa diselesaikan (422 `TNA_EVALUATION_NO_AUDIT`).
- **Metrik** memakai mesin Fase 1 dengan layanan, indikator, dan jumlah pembanding milik kebutuhan; hanya periode yang diganti. Kohort **peserta** = roster terkunci yang diaudit; kohort **pembanding** = agent non-peserta yang diaudit di periode baseline dan evaluasi serta lolos `isAgentExcluded`. Pembanding < 5 agent di salah satu periode ditandai "Kelompok pembanding terlalu kecil"; efek bersih hanya dihitung bila kedua kohort ≥ 5 agent di kedua periode. Perbandingan kohort indikatif, bukan bukti sebab-akibat.
- **Verdict** dari populasi periode evaluasi vs target: `tercapai` (tingkat dan sebaran memenuhi), `tercapai_sebagian` (salah satu), `tidak_tercapai` (keduanya tidak). Kalimat utama narasi memakai `baseline_snapshot` beku; drift baseline hitung-ulang ditampilkan sebagai banner bila ≠ 0. Peserta yang tidak diaudit ditandai "Tidak diaudit", bukan nol.
- **Selesaikan:** server menghitung ulang seluruh hasil, RPC membekukan snapshot, verdict, dan nilai peserta. Klien hanya mengirim `conclusion_note`, `follow_up`, dan `expected_updated_at`; body berisi angka ditolak skema strict. Detail `selesai` membaca snapshot tersimpan tanpa menghitung QA ulang.
- **Tindak lanjut:** `selesai_tuntas`, `perlu_rencana_lanjutan`, atau `eskalasi_non_training`. `perlu_rencana_lanjutan` menampilkan **Validasi ulang parameter** ke `/tna/parameter` pada periode evaluasi dengan `previous_plan`; kebutuhan baru menyimpan `previous_plan_id` setelah validasi atomik di database. Rencana kedua pada kebutuhan yang sama tetap tidak diizinkan.
- **Endpoint baru:** `POST /plans/:id/start-evaluation`, `PATCH /plans/:id/evaluation`, `POST /plans/:id/complete`; `POST /plans/:id/cancel` menerima `cancel_reason`; `POST /needs` menerima `previous_plan_id`. Detail rencana menambah `evaluation`, `evaluation_narrative`, `participant_evaluation`, dan `evaluation_period_options`. Konflik/versi basi → 409, validasi bisnis → 422 dengan pesan Indonesia, error database tak dikenal → 503. Setiap transisi sukses mencatat `logActivity` (`module: tna`).
- **Narasi evaluasi** (`buildTnaEvaluationNarrative`) deterministik, tanpa AI: arah tingkat ("turun/naik dari … menjadi …" atau "tetap di …"), sebaran, verdict, perubahan kohort dengan kata turun/naik/tetap, catatan data belum cukup, awalan `Pratinjau:` selama `evaluasi`, dan penutup indikatif. Narasi Fase 1 tidak berubah.
- Schema, guard, dan prosedur rilis/rollback: [database](database.md#tna--evaluasi-pasca-training-fase-2); kapabilitas: [auth/RBAC](auth-rbac.md#tna--evaluasi-fase-2). Kontrak: [rencana Fase 2](../plans/markdown/tna-phase-2.md).

## 10. EFEK — pengecualian agent dari analisis

- Di `/tna/efek/program/$code`, **Pengecualian analisis** menerima agent dan alasan wajib (1–200 karakter setelah trim), maksimal 10 agent unik. Pengecualian berlaku untuk semua keikutsertaan agent dalam program pada filter yang dipilih, bukan menghapus daftar peserta atau mengubah skor SIDAK.
- Filter tersimpan di URL laporan, **bukan pengaturan permanen**. Alasan ikut tautan dan ekspor; jangan memasukkan informasi rahasia. **Sertakan kembali** mengembalikan satu agent; **Reset pengecualian** menghapus seluruh pengecualian, termasuk saat pemuatan gagal. Kembali ke ringkasan EFEK menghapus filter pengecualian.
- **Semua peserta** dan **Setelah pengecualian** membandingkan ringkasan dengan filter periode/tim/sesi yang sama. Metrik program/sesi dan grafik memakai peserta yang disertakan. Tabel tetap menampilkan semua keikutsertaan, skor individu, label **Dikecualikan**, dan alasan. Semua agent dikecualikan menghasilkan nilai agregat kosong, bukan nol atau kesimpulan berhasil.
- Garis pembanding memakai rata-rata layanan pada bulan kalender yang sama untuk KETIK, PDKT, Telefun, dan CERIWIS: rerata skor bulanan tiap agent serta Σ temuan / Σ sesi audit. Semua agent yang diaudit termasuk peserta dan agent yang dikecualikan dari analisis tetap masuk; staff yang ditolak `isAgentExcluded` tidak masuk. Pengecualian analisis tidak mengubah rata-rata layanan. Δ relatif = Δ peserta − Δ rata-rata layanan; bersifat indikatif, bukan kelompok kontrol, karena peserta juga masuk rata-rata. HTML unduhan mencantumkan hasil awal/hasil tersaring, nama dan alasan pengecualian, serta seluruh peserta.
- Kontrak API `GET /api/v1/tna/efek/report` dan `/report/:program`: query opsional `exclusions` berupa JSON `[{"peserta_id":"UUID","reason":"alasan"}]`; payload salah, alasan kosong/terlalu panjang, lebih dari 10 agent, dan ID ganda ditolak 400. ID di luar kohort tidak berpengaruh. Detail menambah `analysis: { all_participants, exclusions: [{ peserta_id, nama, reason }] }` bila ada pengecualian yang diterapkan, serta `participants[].exclusion_reason` pada baris terkait. Kontrak tanpa filter tetap sama; izin `tna.read`, JWT/RLS dan sumber skor SIDAK tidak berubah. Tidak ada migrasi database.
- Proper input APPK dianggap sesuai secara default dengan nilai 3; bobot dan sesi tetap dihitung, tetapi temuannya tidak masuk hitungan temuan. Toggle `Hitung proper input (APPK)` memakai `?proper_input=include` untuk mengembalikan skor SIDAK resmi. Mode yang sama dipakai rata-rata layanan, disimpan pada tautan ringkasan/rincian, dan dicantumkan pada ekspor. Snapshot parameter diawali `Proper Input` (Chat, Email, CSO) atau `Kemampuan Pencatatan` (Call) dikenali tanpa migrasi; rumus skor SIDAK tidak berubah.
- Ringkasan program menyediakan `median_delta` dan `median_relative_delta`, dihitung dari peserta yang dievaluasi dan tidak dikecualikan, dengan pembulatan dua desimal.
- Kartu ringkasan dan rincian menonjolkan median perubahan dibanding rata-rata layanan serta jumlah peserta yang dievaluasi. Formulir pengecualian berada di disclosure "Sesuaikan analisis"; daftar pengecualian dan pembanding semua peserta tetap terlihat. Grafik skor menjaga rentang minimal 10 poin (maksimal 100), sedangkan grafik temuan per sesi selalu berawal dari nol.
- Bukti dan cakupan: [rencana implementasi](../plans/markdown/efek-agent-exclusions.md), Playwright `tna-efek-report-api.spec.ts` (backend/DB lokal nyata) dan `tna-efek.spec.ts` (browser hermetic, 390/1280px, ekspor, pemulihan dan kegagalan).

## 11. Kegiatan Trainers

Laman publik untuk menemukan dokumentasi kegiatan pelatihan melalui poster atau foto per tahun dan program. Pengunjung membuka berkas di Google Drive; folder dapat meminta akses kepada pemiliknya.

- **Routes**: `/kegiatan` untuk publik dan `/dashboard/kegiatan` untuk pengelolaan.
- **Filter publik**: tahun terbaru dengan kegiatan terbit menjadi pilihan awal; `?tahun=` dan `&program=` disimpan di URL. Tanpa filter program, item dikelompokkan mengikuti urutan tetap SOBAT, KETIK, Telefun, PDKT, CERIWIS.
- **Admin/trainer** dengan capability `kegiatan.manage` dapat menambah, mengubah, menghapus, menerbitkan, dan menyembunyikan item. Leader dan agent tidak mendapat akses.
- **Data**: tabel `public.trainer_activities`, bucket Storage publik `trainer-activity-media`. RLS membuat item terbit dapat dibaca publik dan item tersembunyi hanya terbaca admin/trainer. Mutasi dilakukan melalui API backend; bucket tidak menerima penulisan langsung dari browser. Backend menyimpan setiap gambar sebagai WebP selebar maksimal 800 px (orientasi EXIF diterapkan, metadata dibuang); gambar lama dioptimalkan sekali lewat `pnpm --filter @trainers/api optimize:kegiatan-images`.
- **Validasi**: tahun 2020–2100, judul 1–120 karakter setelah trim, tautan HTTPS Drive/Docs, serta gambar PNG/JPEG/WebP maksimal 5 MB.
- **API**: `GET /api/public/kegiatan` tidak memerlukan login dan mengembalikan tahun terbit serta item pada tahun yang dipilih; CRUD ada pada `/api/v1/kegiatan` untuk admin/trainer.
- **Batasan**: menghapus item tidak menghapus objek Storage, dan isi folder Drive tidak dibaca oleh aplikasi.
