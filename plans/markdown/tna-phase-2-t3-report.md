## Writer K15 dan keselamatan migrasi

`CREATE OR REPLACE public.tna_create_need(p_actor_id uuid,p_payload jsonb) RETURNS jsonb` mempertahankan signature, guard service-role sebagai pernyataan pertama, validasi actor kedua, SECURITY DEFINER/search_path, owner, OID, dan ACL. Tidak ada DROP fungsi atau REVOKE EXECUTE. Migrasi hanya memperluas body writer; tidak mengubah tabel, RLS, index unik, ataupun data existing. Migrasi/rollback T1 dan migrasi Fase 1 tidak diubah.

Bila link disediakan, DB memvalidasi tipe/cast UUID, rencana ada dan `selesai`, `follow_up = perlu_rencana_lanjutan`, layanan serta indikator kebutuhan sebelumnya sama. Invalid link → `TNA_PREVIOUS_PLAN_INVALID` sebelum INSERT, bukan hanya validasi HTTP. Link tidak membuat rencana kedua pada kebutuhan lama; index unik tetap menolak itu. Periode payload validasi ulang adalah periode evaluasi dalam alur E2E; RPC tidak menambahkan pembatasan periode baru di luar K15.

Rollback mengembalikan **body writer Fase 1 persis**, tanpa menghapus kolom atau link yang sudah tersimpan. E2E membuktikan OID/owner/ACL tidak berubah dan link existing bertahan. Writer lama kembali mengabaikan link baru; **fitur link/API harus dihentikan atau di-rollback lebih dahulu**, kemudian rollback writer, baru rollback fondasi Fase 2 bila reversible. Tidak mengklaim fitur K15 tetap tersedia saat rollback.

Context7 `/websites/postgresql_17` menegaskan CREATE OR REPLACE mempertahankan ownership/permissions dan tidak boleh mengubah argument/return type. Graphify query `cancelTnaPlan` menemukan caller route, boundary writer, mapper error, read service, dan logActivity; hasil ditelusuri lagi di kode live. Graphify di-update sekali setelah batch kode final, satu AST worker, tanpa LLM.
